# Kimi-K3 原生 MoE：单卡 B200 验证

[English](kimi_k3_moe_b200.md) | [中文](kimi_k3_moe_b200_zh.md)

这是**单层、单卡诊断基准**，不是 Kimi-K3 服务端基准。OperatorX 在第 1 层调用
vLLM 0.29.0 的原生 `KimiMoE`，使用确定性的合成 BF16 输入和格式有效的打包
MXFP4 路由专家权重。计时边界从 BF16 隐状态开始，涵盖路由、潜在空间投影、
SiTU 路由专家、路由输出归一化、共享专家路径和最终输出。第 0 层是稠密层，
不在此基准内。此基准不包含注意力、残差、检查点权重或 TP/EP 通信。
请求的 Hugging Face 模型版本为 `f831ab66814297da540d832a5235f8e904f29d06`。

六个案例固定模型版本、几何形状、精度、合成数据种子、并行拓扑、执行模式和
缓存策略，仅改变 token 数量及解码/预填充阶段。解码 token 数表示一次模块
调用的输入数量，不是上下文长度，也不是实际 InferenceX 服务批次。

## B200 观测结果，2026-10-07

所有案例均通过输出形状、BF16 类型、有限值、精确重复性和 top-16 分配检查。
计时使用 10 次预热、100 个 CUDA event 样本，每次测量前尽力清除 L2 缓存。
追踪在独立的非权威计时流程中采集。

| 阶段 | Tokens | 中位数 (µs) | p90 (µs) | CV | 分配数 | 活跃专家数 | 追踪中的内核数 / 流数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 解码 | 4 | 1,534 | 1,568 | 1.61% | 64 | 62 | 35 / 2 |
| 解码 | 8 | 1,549 | 1,577 | 1.31% | 128 | 119 | 35 / 2 |
| 解码 | 16 | 1,552 | 1,583 | 1.68% | 256 | 226 | 35 / 2 |
| 解码 | 32 | 1,674 | 1,742 | 3.04% | 512 | 404 | 35 / 2 |
| 解码 | 64 | 2,368 | 2,411 | 2.58% | 1,024 | 608 | 33 / 2 |
| 预填充 | 32,768 | 44,239 | 44,988 | 1.11% | 524,288 | 896 | 34 / 1 |

每个案例的丢弃分配数均为零。该后端未暴露计算实际填充后分配数所需的
token block 大小，因此 `padding.status=unavailable` 是有意记录的限制，
并不表示没有填充。

vLLM 实际选择了 `CutlassExpertsMxfp4`，激活操作数和专家权重均为 MXFP4。
追踪独立观察到两次分组 CUTLASS 专家 GEMM、各次 GEMM 前的 MXFP4 激活
转换、`situ_and_mul`、top-k 选择、排序和重排、归一化、普通线性投影及输出
合并。解码追踪使用两条流，但其中 GPU 内核的执行时间区间没有重叠；
两条流本身并不能证明并发执行。预填充追踪使用一条流。仅凭内核名称无法确定
每个投影的操作数形状；内核耗时之和及 profiler 的 CPU 时间也不是权威模块
延迟，因为追踪会改变调度，并且执行可能重叠。

## 来源与限制

租用的 B200 配有 183,359 MiB 显存，NVIDIA 驱动为 580.126.09，PyTorch
为 2.13.0，vLLM 为 0.29.0。实际运行使用复制的 Python 环境，**没有使用**
`containers.toml` 中配置的容器摘要。由于适配器文件复制到了有未提交更改的
远程检出，运行 JSON 记录的基础 Git SHA 为 `c3c4dd8ed`。原生适配器随后
提交为 `a3148560b`；不能将本次结果描述为来自不可变镜像或干净检出。
原始 JSON 和六份压缩追踪保存在本机已忽略的
`operatorx/results/kimi_k3_b200_20261007/` 目录中；传输后六份追踪的
SHA-256 均与记录值一致。

K3 论文描述的专家权重为 MXFP4、激活为 MXFP8，而此固定版本的 vLLM
实际选择了 MXFP4 激活操作数。这是实测实现选择，不能据此声称 K3 一律
使用 W4A4，或本合成数据与生产服务完全一致。合成权重和零校正偏置不会
复现检查点的路由分布。正确性检查覆盖重复性和结构不变量；完整 K3 层的
独立数值参考仍待实现。预填充案例是一次 32,768-token 模块调用，不模拟
服务端分块或调度。

升级后的运行环境还通过了 DeepSeek-R1-0528 解码 4-token 回归测试；首次
编译 FlashInfer 后，中位数为 1,068 µs。不能用这一数字与 K3 比较模型
质量或服务效率：两者架构、专家数量和精度路径均不同。
